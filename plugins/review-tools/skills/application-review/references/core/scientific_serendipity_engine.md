# Scientific Serendipity Engine

## Purpose

Orchestrate wider conceptual search before narrative optimization, then apply
ruthless scientific filtering. The desired result is surprising but defensible
science; novelty is optional and rigor is mandatory.

Use one orchestrator with reusable reasoning operators, not a permanent team of
personas.

## Full Pipeline

For an adapter with `serendipity_mode: full`, use this conceptual order:

0. Resolve task and adapter.
1. Resolve human constraints, Human Position, and document maturity.
2. Run existing completeness/evidence checks where applicable.
3. Build the compact Scientific Model and Anomaly Register.
4. Run Blind Serendipity Exploration.
5. Apply the Scientific Coherence Firewall.
6. Profile admitted candidates for Scientific Interestingness/Leverage.
7. Assign Four-Quadrant scientific classes.
8. Synthesize and cluster candidates.
9. Send baseline plus admitted alternatives to the Architecture Candidate Engine.
10. Run specialist, outsider, and rubric review.
11. Apply the Change Budget.
12. Apply existing decision and Human Scientific Owner gates.
13. Implement only approved or existing-policy-safe edits.
14. Run existing QC, Voice, Tone, and Authenticity controls in their established order.
15. Update authorized Serendipity Memory.

For grants, the Proposal Completeness, Significance, and Citation Gate remains
early and never moves behind architecture selection. `narrative_only` skips
scientific divergence and may operate only in narrative space. `off` bypasses
this engine.

## Blind Divergence Boundary

The divergence pass may receive only authorized scientific material, the
Scientific Model, essential human constraints, and locked/rejected decisions
needed to avoid prohibited reopening. Do not expose current candidate rankings,
reviewer preference scores, an architecture winner, expected evaluation-gain
ranking, or wording-level alternatives to this pass.

Generate alternatives before criticizing or ranking them. Reviewer-risk
optimization must not suppress unconventional candidates before explicit
coherence analysis.

## Required Operator Library

Select a task-relevant subset automatically:

1. **Assumption Inversion** — test whether an obvious premise is false,
   conditional, reversed, or regime-specific.
2. **Causal Inversion** — compare `A -> B`, `B -> A`, `A <- C -> B`, and
   `A <-> B` without promoting unsupported forms.
3. **Hidden-Variable Search** — seek an unmodeled variable connecting
   observations.
4. **Scale Transfer** — test molecular through collective or temporal scales;
   never assume transfer is valid.
5. **Boundary Redefinition** — question the analytical unit.
6. **Anomaly-First Reasoning** — begin with the observation least compatible
   with the current model.
7. **Unification / Conceptual Compression** — seek one deeper principle without
   sacrificing explanatory accuracy.
8. **Prediction-First Reasoning** — define a sharply distinguishing result and
   reason backward to alternative models.
9. **Constraint Removal** — distinguish biological, empirical, methodological,
   historical, and assumed constraints.
10. **Temporal Reframing** — test timing, order, adaptation, hysteresis, memory,
    accumulation, or repeated exposure.
11. **Population / Heterogeneity Reframing** — test states, subpopulations,
    thresholds, selection, or stochastic transitions.
12. **Cross-Domain Structural Analogy** — follow
    `cross_domain_analogy_engine.md` exactly.

## Candidate Contract

Represent baseline and alternatives with the same schema:

```text
Candidate ID
Candidate family
Origin operator
Core concept
Difference from current model
Evidence already supporting it
Evidence conflicting with it
Required assumptions
Causal chain
Predictions
Discriminating prediction
Alternative explanations
Potential scientific payoff
Current uncertainties
Implementation implications
Scientific/narrative space label
Literature novelty: NOT VERIFIED
```

Candidate families include `baseline-near`, `assumption-shift`,
`mechanism-shift`, `anomaly-derived`, `cross-domain-derived`, `scale-shift`, and
`unification`. Cluster by causal model, assumptions, and prediction delta.
Multiple rephrasings of one mechanism are one family.

## Evaluation And Synthesis

Run the firewall in `scientific_coherence_firewall.md` before interestingness.
Keep the baseline as comparator. Preserve promising firewall failures only as
Speculative Seeds. Identify Pareto-relevant admitted survivors and pass a small
set of genuinely distinct models to narrative architecture. Zero unconventional
survivors is an explicit successful outcome; never fabricate novelty.

Do not choose a winner merely because it is smooth, reviewer-familiar, or
stylistically conventional. Do not infer scientific novelty from a narrative
reorder or literature novelty from conceptual surprise.

## Premature-Convergence Protection

Detect mode collapse when alternatives differ mainly in wording, preserve the
same assumptions, disappear before explicit firewall review, optimize reviewer
familiarity too early, or repeatedly converge on generic grant language.

When detected, run exactly one targeted divergence recovery pass with an
operator absent from current families. Then recluster and reevaluate. Maximum
automatic recovery passes: `1`; deeper recovery requires explicit user request.

## Human And Action Boundaries

Apply `LOCKED`, `PREFERRED`, `OPEN`, `DISLIKED`, and
`REJECTED_UNLESS_NEW_EVIDENCE` positions from existing decision memory. A
conflict with `LOCKED` is non-actionable unless explicitly reopened. Reopen a
rejected idea only when genuinely new evidence plausibly meets its recorded
condition, and rerun the firewall.

Scientific class (`SAFE BASELINE`, `TARGET`, `SPECULATIVE SEED`, `REJECT`) and
change risk (`Green`, `Yellow`, `Red`) are separate. Record domain risk on its
own axis as `NONE`, `SPECIALIST_REVIEW_REQUIRED`, or `CLEARED`. Exploration may
be broad, but Sprint auto-implementation remains limited to meaning-preserving
changes already safe under existing policy and without unresolved domain risk.
GatedSprint Phase 1 remains proposals only.

## User Burden And Performance

Use compact models, adaptive depth, operator selection, clustering, one recovery
pass, deduplicated memory, and a small surfaced subset. Normal output includes
at most two or three coherent unconventional survivors and one to three
important seeds. Do not expose every operator, rejected candidate, score table,
analogy, or memory entry unless detailed diagnostics are requested.
