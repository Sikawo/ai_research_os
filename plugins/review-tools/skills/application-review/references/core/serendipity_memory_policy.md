# Serendipity Memory Policy

## Purpose

Preserve a small amount of high-value scientific exploration state across
authorized runs without creating a duplicate project-status, work-queue,
revision-log, or general decision system.

## Durable Contents

Persist only:

1. materially relevant anomalies;
2. Speculative Seeds with rescue and reopen conditions;
3. cross-domain analogies worth revisiting;
4. reopen triggers;
5. human conceptual constraints only when existing decision memory cannot
   adequately represent them.

Scientific Model snapshots and transient rankings normally remain run artifacts.
Do not persist every brainstorm, near-duplicate ideas, wording advice, ordinary
reviewer comments, or unsupported claims as facts.

## Stable Records

Use stable prefixes `ANOM-`, `SEED-`, and `ANLG-`. Deduplicate by concept,
mechanism, required assumptions, and predicted outcome, not wording alone.

Seed records must include concept, origin, why interesting, present failure,
missing bridge and evidence, evidence that would weaken or rescue it,
discriminating test, payoff, related anomalies, human position, reopen
condition, and one status: `DORMANT`, `WATCH`, `REOPENED`, `REJECTED`, or
`PROMOTED`.

## Future-Run Protocol

At the beginning of an eligible run:

1. read only relevant memory within the authorized scope;
2. identify genuinely new evidence or observations;
3. compare them with explicit reopen conditions;
4. reopen only entries whose trigger is plausibly met;
5. rerun the Scientific Coherence Firewall;
6. never promote a seed because it is old, memorable, or repeatedly surfaced.

## Human Position Integration

Use existing revision decisions and do-not-change structures before adding any
conceptual constraint here. Supported positions are:

- `LOCKED`: no actionable alternative unless the user explicitly reopens it;
  a valuable conflict may remain a non-actionable counterfactual.
- `PREFERRED`: displace only with a clear advantage.
- `OPEN`: normal exploration.
- `DISLIKED`: deprioritize absent a substantive new reason.
- `REJECTED_UNLESS_NEW_EVIDENCE`: reopen only when the recorded trigger is met,
  and state the new evidence that caused reconsideration.

## Protection And Provenance

Memory inherits the protection level and access boundary of its source. Do not
move protected ideas to generic/public/shared-core files, read cross-project
private memory for inspiration, search unrelated research areas, or expose
unpublished hypotheses in templates or tests. Read permission does not imply
write permission. Personal Cross-Pollination remains unavailable without a
separately authorized positive source scope and recorded provenance.
