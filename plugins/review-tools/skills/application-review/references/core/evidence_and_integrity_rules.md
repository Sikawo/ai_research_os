# Evidence And Integrity Rules

These rules apply to every Application Review OS mode.

## Anti-Impersonation

Reviewer backgrounds are public-information-derived field perspectives. They
must not be written as simulations of real people.

Do not claim:

- actual reviewer assignment;
- private reviewer opinions;
- confidential institutional preferences;
- personal motivations or personality traits;
- guaranteed outcomes;
- hidden committee dynamics.

Safer wording:

```text
Based on public program materials and visible field priorities, reviewers in
this context may prioritize...
```

## Evidence Labels

Use these labels when evidence strength matters:

- `official requirement`: from an official call, guideline, or user-provided
  official excerpt.
- `public background`: from public institution, program, lab, or field
  information.
- `user-provided`: from text or facts supplied by the user.
- `inference`: a reasoned conclusion from available evidence.
- `uncertain`: plausible but not yet verified.
- `missing`: required evidence is not available in the current context.

## Scientific Integrity

Never fabricate:

- citations;
- publication status;
- acceptance, revision, or submission status;
- results or preliminary data;
- protocols;
- budget rules;
- staffing constraints;
- institutional requirements;
- collaborator commitments.

When a user mentions a new achievement, such as an accepted paper, treat it as
user-provided until an allowed source confirms it. Do not spread it into other
documents without checking status consistency.

## Sprint Integrity

During `Sprint`, do not:

- invent reviewer identities or private reviewer opinions;
- claim to know actual reviewer assignments;
- change publication status without explicit evidence;
- add new preliminary data unless present in authorized source material;
- add new experiments unless listed as a human-decision proposal or clearly
  requested;
- turn missing evidence into a confident claim;
- alter the applicant's core scientific intent for rhetorical smoothness.

If evidence is missing, mark it as `missing`. If a point is plausible but not
verified, mark it as `uncertain`.

## Private-Content Boundary

Do not read protected application content, paper notes, PDFs, meeting notes,
raw data, analysis exports, or collaborator context unless the user explicitly
names the allowed file, folder, excerpt, and purpose.

Do not inspect protected content merely to decide whether it is sensitive.

## Repeated Advice Integrity

Repeated advice can become misleading because it makes stale ideas feel newly
validated. Before repeating advice:

- check whether it is already in a revision decision log;
- state whether the advice is new, deepened, already known, or retired;
- avoid repeating generic advice unless it now has a concrete implementation
  detail or a new reviewer/rubric consequence.
