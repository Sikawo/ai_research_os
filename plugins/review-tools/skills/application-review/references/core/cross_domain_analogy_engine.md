# Cross-Domain Structural Analogy Engine

## Purpose

Use cross-domain structure to generate defensible scientific leverage without
promoting keyword resemblance or decorative metaphor as science.

## Required Procedure

1. **Abstract the target problem.** Write a domain-independent signature, such
   as `multiple weak inputs -> integration -> threshold crossing -> switch-like
   output -> delayed negative feedback -> adaptive threshold`.
2. **Choose a justified source domain.** Possible domains include control
   theory, neuroscience, ecology, evolutionary theory, statistical physics,
   information theory, network science, distributed systems, reliability
   engineering, dynamical systems, economics, decision theory, and materials
   science. Do not force a distant domain for novelty theater.
3. **Map components explicitly.** Pair every relevant source component,
   relationship, boundary, and timescale with the proposed target counterpart.
4. **Perform mismatch analysis.** State where the analogy breaks, why each
   mismatch matters, and which conclusions cannot transfer.
5. **Demand leverage.** State the new discriminating prediction or the
   explanatory work that the mapping adds beyond the baseline.

An analogy without explicit mismatch analysis cannot become a scientific
candidate.

## Analogy Verdicts

Use exactly one primary verdict:

- `NEW DISCRIMINATING PREDICTION`
- `NEW EXPLANATORY LEVERAGE`
- `USEFUL HEURISTIC ONLY`
- `METAPHOR ONLY`
- `INVALID ANALOGY`

`METAPHOR ONLY` is narrative material, not scientific novelty. A critical
invalidating mismatch limits the result to `USEFUL HEURISTIC ONLY` or
`INVALID ANALOGY`. Only the first two verdicts may proceed to candidate
evaluation, and they must still pass the Scientific Coherence Firewall.

## Analogy Record

```text
Analogy ID
Target structural signature
Source domain and source structure
Explicit component mapping
Relationship and scale mapping
Material mismatches
Unsafe transfers
Prediction delta
Explanatory leverage
Verdict
Evidence status
Provenance
Revisit condition
```

Do not infer literature novelty from the analogy. Do not search externally as
part of Sprint or GatedSprint.

## Personal Cross-Pollination

Personal Cross-Pollination is an optional architecture contract and is disabled
unless the user explicitly authorizes a bounded source scope. When separately
authorized, abstract the current structure, search only the named personal
sources, map similarities and differences, apply this contract and the
coherence firewall, and record provenance.

Never read unrelated private research areas for inspiration. Never move
protected hypotheses into generic templates, shared-core files, or synthetic
tests. This contract does not itself authorize access to any personal research
source.
