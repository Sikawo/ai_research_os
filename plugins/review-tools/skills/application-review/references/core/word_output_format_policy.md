# Word Output Format Policy

## Purpose

Create or materially reformat Word outputs that remain readable to a tired
scientific reviewer without violating official templates, page limits, required
content, source meaning, evidence integrity, or approval boundaries.

This policy is a default adapter for `Sprint` and `GatedSprint`, not permission
to overwrite an official template or restyle a document whose current formatting
the user asked to preserve.

## Activation

Apply this policy when Sprint or approved GatedSprint Phase 4:

- creates a new DOCX;
- converts approved text into a DOCX;
- materially reformats an authorized Word source; or
- proposes a research-plan page and figure layout.

For a light wording edit, preserve the authorized source formatting unless the
user explicitly requests reformatting or a serious readability/submission issue
requires a proposal. GatedSprint Phase 1 may produce a layout plan and figure
concepts only; it must not create or edit the final Word file.

## Artifact and layout authority

Resolve these fields before making or reviewing a layout:

- content authority;
- layout authority;
- editable target;
- DOCX/PDF equivalence status; and
- the user's `current`, `candidate`, `submitted`, or `final` designation.

Do not infer one field from another. A user-designated current, submitted, or
final PDF is layout authority. A PDF produced by this workflow from DOCX is a
`PREVIEW_NON_AUTHORITATIVE` artifact until compared with the user's actual
export and verified as equivalent. A DOCX-only route supports content editing,
but layout is `NOT_ASSESSABLE` when only an unverified preview exists.

Never silently review content from one version and layout from a divergent
version. Same-content companion formats may share a version identity only after
equivalence is verified; divergent DOCX/PDF content requires distinct version
identities. If a submitted/final PDF is designated, it controls the release
layout and makes unresolved editable-source assumptions stale. Inspect the exact
final artifact before release. Any later edit, conversion, or export produces a
new unverified candidate.

## Priority Order

Resolve conflicts in this order:

1. official target template, page limit, font floor, and mandatory content;
2. scientific/factual accuracy and source meaning;
3. complete, coherent argument and required sections;
4. tired-reviewer readability and page-level visual hierarchy;
5. preferred visual allocation;
6. default typography settings in this policy.

An official or user-approved requirement may override a default. Record the
override and reason. Never claim full compliance when the rendered file was not
checked or a conflict remains unresolved.

## Default Typography

Use these defaults when no controlling template specifies otherwise:

| Element | Default |
| --- | --- |
| Body | Arial 11 pt; justified |
| Body line spacing | Multiple `1.12` |
| Paragraph spacing | `0 pt` before; `3 pt` after |
| Headings | Arial `12–13 pt`; bold; left-aligned |
| Figure captions | Arial `9–9.5 pt`; left-aligned; normally `1.0–1.05` line spacing |
| Narrow text beside a figure | Left-aligned |
| Figure-internal text | Left-aligned by default |
| Margins | `0.72–0.75 inch` |
| Main-text density with a figure | Approximately `500–600 words/page` before page-specific adjustment |
| Paragraph size | Normally `2–4 sentences`, approximately `60–100 words` |

For justified body text, avoid manual line-break abuse and inspect for excessive
word-spacing rivers, short stretched lines, and broken technical terms. Do not
justify headings, captions, narrow figure-side text, or placeholder contents.

## Adaptive Page Budget

Resolve the official page limit and mandatory sections before assigning figures
or word targets. `500–600 words/page` is a planning range, not a compliance
guarantee or a reason to delete necessary science. Lower the target when
headings, citations, tables, captions, references, or required administrative
content occupy substantial space.

When the rendered document overflows, adjust in this order:

1. remove redundancy and compress wording without changing meaning;
2. shorten figure-placeholder and caption text;
3. reduce a visual from about `25%` toward `20%`, then `15%` of usable page
   area;
4. omit, move, or combine a low-value visual anchor;
5. reduce paragraph-after spacing from `3 pt` to `2 pt`;
6. reduce body line spacing from `1.12` to `1.10`, then `1.08`;
7. reduce margins toward `0.70 inch`;
8. stop and disclose the unresolved conflict.

Do not reduce body text below `11 pt`, line spacing below `1.08`, or margins
below `0.70 inch` merely to preserve a preferred layout. A controlling official
template may require different values, but the output must state that the
official rule caused the deviation.

## Page-Adaptive Visual Plan

Apply the visual-first behavior only to scientific research plans, research
statements, grant or fellowship proposals, and PI or group-leader scientific
program documents. Do not force scientific figures into ordinary cover letters,
recommendation or reference letters, CVs, personal statements, or other
non-scientific career documents.

For an eligible scientific document, actively test one meaningful visual anchor
per substantive research-plan page and default toward one when it materially
reduces cognitive load or increases evidentiary confidence. This is a strong
planning default, not a rigid figure quota. Omit a visual when it adds no real
explanatory value.

For each substantive page, record:

1. page or section;
2. narrative job;
3. main reviewer doubt;
4. whether a visual would resolve that doubt faster than prose;
5. visual recommended: `yes` or `no`;
6. visual function and figure or placeholder type;
7. one-sentence evidence-calibrated take-home message;
8. evidence/provenance boundary;
9. approximate page-area budget; and
10. reason for omission when no visual is recommended.

Select only a visual that answers a meaningful reviewer question and performs
real explanatory work. Candidate functions include:

- program overview or central model;
- accomplishment-to-future-program bridge;
- Aim, project, or work-package logic;
- mechanism or causal model;
- discriminating prediction;
- integration across projects;
- decision tree, risk, or alternative-strategy logic;
- timeline or milestone structure.

Adapt the count to actual page limits. A reference-heavy, budget-heavy,
administrative, or conclusion page may use a smaller visual, a Key Takeaway box,
or no figure. Short closing pages and pages whose argument is already visually
trivial may also omit a figure. Do not repeat the same model, add a decorative
graphic or redundant visual, displace essential science, or move required text
merely to satisfy the planning default. Do not place a figure before the
minimum concepts needed to interpret it.

The normal visual allocation is approximately `25%` of usable page area,
adaptable within about `15–25%`. Treat the title, placeholder content, and
caption as part of that budget.

When a substantive figure occupies page space, approximately `500–600
words/page` remains a planning-density target, not a hard limit.

## Overview-First, Evidence-Next Architecture

For an eligible scientific research plan, treat an early overview cartoon,
central model, or program-level schematic as the preferred first major visual
when it would help orientation. It should let the reviewer reconstruct the
important problem, organizing concept, relationship among Aims or Projects,
central causal or quantitative logic, and applicant-specific framing without
reading detailed text.

After that overview, select the visual that resolves the most important reviewer
doubt on the page. Prefer preliminary or published data when the doubt concerns
credibility, feasibility, mechanism, or applicant ownership. Do not hard-code
later figures as preliminary data. Integration schematics, causal models,
decision trees, discriminating predictions, risk/alternative logic, timelines,
or accomplishment-to-future bridges may be better when they answer the actual
reviewer question.

Every major figure should communicate an argument rather than merely illustrate
content. Whenever possible, the page's central argument should remain
reconstructable from the figure and its caption without detailed body text.

Classify Figure 1 before assigning it coverage requirements:
`PROGRAM_OVERVIEW`, `CENTRAL_MODEL`, `ANCHOR_EVIDENCE`, or
`OTHER_JUSTIFIED_ROLE`. Build a program-to-surface coverage map that records the
dominant surface for all major
pillars, Aims, or branches. When Figure 1 is the designated program overview,
it must include every major branch at the correct evidence, hypothesis, or
proposed-work status. When Figure 1 serves another legitimate role, do not
overload it merely for symmetry; designate another visual or textual surface
that integrates the full program. A branch present only in detailed body text
does not satisfy dominant-surface coverage.

## Preliminary Data Policy

Preliminary data can establish that a phenomenon is real, demonstrate
feasibility, support a mechanism, show applicant ownership or traction, and
turn an attractive idea into a credible program. Prefer them when one of those
is the page's main reviewer doubt, but do not require preliminary data on every
page.

Do not create a mini-R01 by filling a research statement with small data panels,
overload a faculty or PI statement with A–F panel density, or let data quantity
obscure the intellectual program. In PI, faculty, and tenure-track research
statements, use preliminary data as proof of traction, not as an excuse to turn
the document into a grant application. Never invent data, experiments,
quantitative values, significance, or mechanistic certainty.

## Visual Evidence Boundary

Label visual content and caption claims as published result, preliminary result,
hypothesis/model, proposed experiment, expected outcome, or future implication.
Never invent data or an experiment, invent a quantitative relationship, turn a
hypothesis into an established mechanism, visually imply unsupported causality,
or use a cleaner schematic to silently increase certainty. When rendered visuals
are unavailable, record visual-quality judgments as `NOT ASSESSABLE` rather than
inferring them from captions or extracted text.

## Concept-Only Figure Placeholder

Do not force figure generation. When no authorized figure exists, use
`templates/word_figure_placeholder_template.md` and reserve a stable concept
space containing:

1. figure number or placeholder ID;
2. concise figure title;
3. one-sentence take-home message;
4. two to four simple components or panel/layout instructions;
5. suggested figure type;
6. evidence/provenance status and `No invented data` boundary.

The placeholder is a design instruction, not scientific evidence. It must not
invent a result, experiment, citation, quantitative relationship, image, or
mechanism absent from authorized sources.

For Word stability, prefer a non-floating one-cell table with a thin border and
optional light neutral shading. Keep it inline with text, prevent row splitting,
and keep its title/content/caption unit on one page when possible. If a one-cell
table damages the controlling template, reserve bordered blank space or stable
paragraph spacing instead. Avoid floating rectangles and text boxes by default
because later edits can change their anchors and text wrapping.

Figure captions must communicate the take-home message rather than merely list
visible objects, methods, or systems. Figure titles and captions must communicate
an evidence-calibrated scientific take-home.
Keep captions, narrow figure-side text, and figure-internal text left-aligned.

## Tired-Reviewer And Rendering QC

When tooling permits, render the DOCX or inspect equivalent page images before
delivery. A generated preview supports QC but does not replace the actual layout
authority. Check:

- actual page count against the official limit;
- headings kept with the following paragraph;
- no page-bottom orphan heading;
- widows, orphans, and isolated one-line paragraph fragments;
- no split placeholder, figure, or caption unit;
- no unstable overlap or floating-object displacement;
- justified-body spacing rivers or stretched short lines;
- visual and caption legibility at realistic review size;
- figure sequence and proximity to the text that needs it;
- adequate white space without an accidentally blank or underfilled page;
- consistent heading, caption, figure, margin, and paragraph styles;
- unchanged scientific/factual meaning after pagination edits.

If rendered visual inspection is unavailable, mark page-level, spacing, and
visual-quality judgments as `NOT ASSESSABLE` rather than inferring them from
captions or extracted text.

Before submission or release, repeat the applicable checks on the exact
user-designated final PDF (or other controlling final artifact) and bind the
result to its identity or hash. Folder-current status, a clean preview, or an
earlier verified export is insufficient. Any subsequent edit or export resets
layout verification.

## Sprint And GatedSprint Authority

`Sprint` may apply these layout defaults only within existing safe auto-edit
authority and the resolved document/adapter constraints. High-tradeoff content
cuts, figure additions or data selections, figure concepts that alter scientific
emphasis, major page rearchitecture, or deviations from an official template
remain decision-gated.

`GatedSprint` Phase 1 may recommend typography, page allocation, figure concepts,
and placeholders but may not generate a figure or create/edit a final DOCX.
Phase 3 must identify the approved page/visual plan. Phase 4 may create or
reformat the DOCX only after explicit approval, then run page-aware format QC
and rerun the Tired Brilliant Outsider reconstruction and visual-narrative tests
after pagination and before final delivery.

## Required Disclosure

The output or change report must record concisely:

- controlling official/template constraints;
- resolved font, alignment, line spacing, paragraph spacing, and margins;
- final page count and page-specific visual/placeholder plan;
- content authority, layout authority, editable target, and equivalence status;
- whether any inspected PDF was authoritative or only a generated preview;
- exact-final-artifact identity and verification state;
- deviations from defaults and reasons;
- unresolved page-limit, rendering, or format-preservation risks;
- whether placeholders are concept-only and contain no invented data.

Do not expose every small pagination adjustment unless the user asks.
