# Core Command Policy

> **SHARED CORE** — canonical source: `ai_research_os/shared_core`. Do NOT edit in a
> downstream repo. Edit only in `ai_research_os`, then re-sync. Version: 2026-05-22.

Source: consolidated from `AGENTS.md` (implementation-side command policy),
`Docs/claude_permission_policy.md`, and `Docs/command_wrappers.md`. No new policy
is introduced here. A repository's `.claude/settings.json` is adapter
configuration and must not override this policy; if they disagree, repository
policy wins and the tool should stop and ask the human.

## Allowed without extra human confirmation

Allowed for an implementation-side AI tool when staying inside the approved
spec or task:

- `git status`, `git status --short`
- `git diff`, `git diff --check`, `git diff --cached --check`
- `git branch --show-current`
- `git log --oneline -5`
- `mkdir -p exports/active_change`
- preserving the exact approved spec at `exports/active_change/CHANGE_SPEC.md`
  after confirming there is no different active spec already present
- proceeding with implementation when the only pre-existing working-tree change
  is `HANDOFF.md` generated by `Scripts/start_change.py` for the same current
  task
- `python3 Scripts/finalize_completed_change.py --archive-active-spec` only
  after final review approval, human commit, human push, and a clean working
  tree
- reading committed text-only workflow files needed for the task
- editing files named by the approved positive file list
- Python syntax checks such as `python3 -m py_compile ...`
- `python3 Scripts/run_safety_check.py`
- `python3 -m pytest`
- `python3 Scripts/finish_change.py`,
  `python3 Scripts/finish_change.py --spec exports/active_change/CHANGE_SPEC.md`,
  or `python3 Scripts/finish_change.py --active-spec`
- generating review packets under `exports/`

## Ask first

Ask the human before:

- modifying files outside the approved positive file list
- modifying negative-list files
- continuing implementation when `git status --short` shows any pre-existing
  change other than same-task `HANDOFF.md` generated by
  `Scripts/start_change.py`
- replacing `exports/active_change/CHANGE_SPEC.md` when it already exists and
  differs from the received approved spec
- archiving or clearing an active spec before final review approval, human
  commit, human push, and a clean working tree
- changing tests beyond task scope
- changing Python scripts
- changing `.gitignore`
- changing dependencies or lockfiles
- running `git pull`, `git fetch`, `git merge`, or branch switches not explicitly
  approved
- installing packages, using network access, or calling external APIs
- uploading repository contents or sending them to external AI tools
- changing security, external-AI, or review-workflow behavior beyond the spec

## Forbidden unless explicitly approved in the active spec

- `git add`, `git commit`, `git push`
- opening pull requests
- creating or switching branches (except when the active spec or policy approves
  creating the named feature branch)
- branch deletion
- `git reset --hard`, `git clean`
- `rm`, `rm -rf`, deleting, moving, or renaming files
- cleanup of generated exports outside the guarded post-review workflow and
  completed-active-spec finalization helper
- committing generated `exports/`
- external uploads or auto-sending repository contents to external AI tools
- reading, modifying, moving, renaming, deleting, summarizing, exporting, or
  staging raw data, papers, PDFs, images, notebooks, secrets, credentials,
  tokens, private keys, `.env` files, local workspace state files, or
  institutionally restricted content
